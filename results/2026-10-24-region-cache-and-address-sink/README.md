# Region cache invalidation and address-candidate compaction

Two independently validated compiler costs were removed. The deployed ZLUDA
compiler was relinked with both changes. No hardware ISA encoding or
simulator timing parameter was changed.

## Checkpoints

* LLVM `8c350523dde0`: track regions with nonempty node caches. Global
  invalidation clears those maps immediately, avoiding a recursive walk over
  every region after each region pass. Local clearing, destruction, moves,
  release and recalculation maintain the owner set. Move assignment releases
  the destination's previous region tree before transferring ownership.
* LLVM `46aff3aba735`: nested divergent-region/loop functional fixture.
* LLVM `c1a33023280a`: compact rejected address candidates once per fixed-point
  round with SetVector::remove_if. The prior loop removed each candidate
  individually, repeatedly searching and shifting its ordered vector. Removal
  order and membership updates remain the same.
* Simulator `30a17d3` and `721523a`: corresponding reproducible functional/cost
  checks and results. No modeled shader cost was retuned to describe host
  compilation work.

## Blender region normalization

The same surface-only optimized LLVM IR was compiled through structurization
with the pre-cache-change and changed compilers:

| Measurement | Before | After |
| --- | ---: | ---: |
| Process wall seconds | 137.784 | 105.882 |
| Timed backend pass seconds | 93.389 | 89.912 |
| Structurization pass seconds | 77.044 | 73.764 |

This paired observation reduces wall time by 23.2%. The pass manager's cache
clearing sits outside individual transformation timers, so their summed
changes do not account for the entire wall-time difference. The earlier
instrumented 67,000-region sample had already attributed 23.484 seconds to
these cache walks. This is a partial compilation measurement, not a render
speedup. Small test builds/checks overlapped the runs; no repeated,
clock-controlled performance distribution is claimed.

Both output MIR files are 1,192,567,545 bytes and have SHA-256
`8120ab5a912f2d80fea5178efa4c6c4cd18ac91f838725bf628ae1a374d49e8a`.
The duplicate before dump was removed after hashing. The after checkpoint is
retained under `/scratch/agx-region-cache/surface-after.mir`. Numeric commands,
wall measurements and pass profiles are retained here.

## Address sinking

Resuming that checkpoint originally reached AGXSinkAddresses and remained
there when the 240-second external check expired. With bulk compaction,
that pass completes in 1.3665 seconds and the resumed partial pipeline exits
zero in 31.366 seconds, including parsing/printing the large MIR. The two
wall measurements have different stopping points, so they are not an exact
whole-compile speedup ratio. The before log ends inside address sinking;
the after pass's own timing is retained in its diagnostic evidence.

An independent authored fixture generated by
`scripts/generate_address_rejections.py` creates 50,000 full-width integer
values used by volatile stores, which must be rejected for narrowing.
Its address-sinking pass falls from 0.2248 to 0.0045 seconds. Process wall
times are 0.4645 and 0.2144 seconds. Both post-pass IR dumps are identical:
7,718,641 bytes, SHA-256
`004996700c63dd74634db534456dc00dde5e8ff6e2a0a848ea1f2a2d31d5bd32`.
This is one synthetic pair, not a prediction of application runtime gains.

```bash
python3 scripts/generate_address_rejections.py /scratch/reject.ll
llc -mtriple=agx -mcpu=agx-g14c -O0 \
  -stop-after=agx-sink-addresses -time-passes -o /dev/null /scratch/reject.ll
```

For correctness, the three existing address-sinking/threadgroup-offset
fixtures produce byte-identical live code with the before/after compilers
on both G13G and G14C (`sink-fixture-code.json`).

## Correctness and applications

All 133 available AGX, generic structurization and region-analysis regression
tests pass; three AMDGPU-only cases are unsupported in this build. After
address compaction all 79 AGX tests pass again. Eight new cache-lifetime unit
tests pass in a standalone AddressSanitizer/LeakSanitizer-linked runner using
the release LLVM archives; the archives themselves are not fully sanitizer
instrumented. Assertions remain enabled in the production LLVM build.

The simulator's nested-loop fixture checks 32 lanes at trip counts 0, 1, 4
and 9 on G13G/G14C: all 256 current and 256 baseline lane results match the
independent integer oracle. Live code (256 bytes per target), execution and
predicted cost agree. The gate was rerun with the pre-address-compaction
compiler as baseline. See the simulator's matching results directory.

After both changes, supplied Qwen counting inference exits zero and matches
the CPU output exactly, with 39 compilations. The CUDA hardware smoke test
reports zero wrong results over 50,000 elements, graph replay, unified memory,
and 2D copies. These validate the rebuilt compiler, not a controlled timing
comparison: other validation processes overlapped them.

Geekbench 7.1.0 ARM64 reaches all eleven workloads. It records 2,026 compiler
invocations and eleven expected error-701 launch-resource tuning rejections,
then exits 255 when network upload fails. Wall time is 129.623 seconds; no
published score or overall Geekbench speedup is established.

## Remaining full-shader validation

Resuming the saved MIR past address sinking reaches instruction selection
and reports:

```
LLVM ERROR: Cannot select: ... i32 = addrspacecast[0 -> 5] Constant:i64<-1408>
```

`private-cast-repro.ll` isolates the same failure without executing an invalid
GPU memory access. Both the pre-compaction and changed compiler reject it
with the same unsupported DAG operation (`private-cast-comparison.json`).
This establishes an existing generic-to-private constant pointer-cast gap.
The original full-source compile still exceeds a 150-second check without
a diagnostic (`surface-full-timing.json`). Consequently, the resumed MIR
error is not proof of its sole remaining blocker. Full Blender compilation
and rendering are still unverified and remain in scope.

The first resumed failure's process duration includes system abort/core
handling and is not a useful successful compile timing. A full-source check
with core dumps disabled and pass timing only is recorded separately.
Per-region debug printing was stopped because formatting unnamed regions
is itself expensive at this shader's size; it is not the reported speedup
measurement. The temporary profiling patch from the previous checkpoint is
absent from the deployed compiler.

The llama-app benchmark also exits zero with GPU offload, flash attention off,
and microbatch 8: pp128 averages 86.840 tokens/s and tg32 35.815 tokens/s over
three repetitions. Other CPU validation was running concurrently, so these
are a working-path check, not an isolated speedup claim (`llama-bench.json`).
`compiler-artifacts.json` records separate file hashes for the two frozen
baselines and deployed compiler, disambiguating commands whose build path
was later updated.
